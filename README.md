# Rift Lab / A1 eSports

GitHub-only League of Legends dashboard for the A1 eSports friend group.

## Architecture

```text
GitHub Actions scheduled job
  -> RIOT_API_KEY from GitHub Secrets
  -> Riot API
  -> data/rift-lab.json
  -> immutable commit on site-snapshots
  -> GitHub Pages
  -> verify public JSON matches the snapshot
```

The browser never calls Riot directly. It only fetches the public processed JSON file generated by GitHub Actions.

## GitHub Setup

1. Open the repository on GitHub.
2. Go to **Settings -> Secrets and variables -> Actions**.
3. Add a repository secret:

```text
RIOT_API_KEY = RGAPI-your-key-here
```

4. Go to **Settings -> Pages**.
5. Under **Build and deployment**, set **Source** to **GitHub Actions**.
6. Go to **Actions -> Update Rift Lab data and deploy**.
7. Click **Run workflow**.

After the workflow finishes, the site is served from:

```text
https://gennnnnnnnn.github.io/a1esports/
```

The workflow maintains a five-minute refresh loop with a scheduled trigger as a backup. Pushes reuse the latest saved data; scheduled and manual runs refresh Riot data. Add `[refresh-data]` to a commit message to refresh data on that push.

Source code stays on `main`. Generated public files and accumulated match/LP history live on the dedicated `site-snapshots` branch. Every publication gets a new, valid commit SHA, which is passed to the Pages deployment API as its build version. Repeated refreshes therefore do not reuse the source commit as their deployment identity.

Each run loads its baseline from snapshot storage rather than the public CDN, then saves the new snapshot before deployment. This preserves collected history even if Pages fails to publish it. Writers are serialized, and snapshot pushes must be fast-forward updates. After deployment, the workflow compares the entire public JSON against the generated file and fails if they differ. The next automatic refresh still runs after a failure.

The workflow requires `contents: write` for snapshot storage, in addition to its Pages, Actions, and OIDC permissions. Keep Pages configured for GitHub Actions; `site-snapshots` is storage, not a branch-based Pages build source.

## Local Commands

Generate sample data:

```bash
npm run update:data:sample
```

Validate scripts:

```bash
npm run check
node --test scripts/snapshot-store.test.mjs scripts/deploy-snapshot.test.mjs
```

Generate live data locally:

```bash
RIOT_API_KEY=RGAPI-your-key npm run update:data
```

On Windows PowerShell:

```powershell
$env:RIOT_API_KEY="RGAPI-your-key"; npm run update:data
```

## Data Shape

```javascript
{
  updatedAt,
  source,
  players: [
    {
      name, riotName, tag, level, puuid, nameHistory,
      soloTier, soloRank, soloLp, soloWins, soloLosses, soloWr,
      flexTier, flexRank, flexLp, flexWins, flexLosses, flexWr,
      notes
    }
  ],
  nameChanges: [
    { player, puuid, from, to, detectedAt }
  ],
  summaryRows: [
    { player, games, wins, losses, winRate }
  ],
  latestNotes: [
    { date, player, scope, summary, strengths, weaknesses, actions }
  ],
  matches: [
    { matchId, player, playerPuuid, riotId, ...matchStats }
  ],
  metrics: {
    trackedPlayers,
    importedMatches,
    bestRecent,
    highestSolo,
    highestFlex,
    worstSolo
  }
}
```

## Riot Routing

The generator preserves the VN2 routing that was already debugged:

```text
ACCOUNT-V1 -> asia.api.riotgames.com
MATCH-V5   -> sea.api.riotgames.com
SUMMONER-V4 / LEAGUE-V4 -> vn2.api.riotgames.com
```

Ranked queues:

```text
420 = Ranked Solo/Duo
440 = Ranked Flex
```

## Security

Do not commit:

- Riot API keys
- `.env` files
- Google OAuth tokens
- private Google Sheet edit links

Only public processed dashboard JSON belongs in this repository.
